# SEO research notes

## Google Search Central sources

- Sitemap guidance: https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap
  - Sitemap should be UTF-8 encoded.
  - Host it at the site root so it can cover the full site; a sitemap can also be submitted in Search Console or referenced from robots.txt with `Sitemap: https://example.com/sitemap.xml`.
  - XML is the appropriate format for this static Vite app.

- JavaScript SEO basics: https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics
  - Google can process JavaScript, but crawlable HTML links should use real `<a href>` elements.
  - Use unique, descriptive `<title>` and meta descriptions, a canonical URL, meaningful HTTP status codes, and JSON-LD when structured data is appropriate.
  - Validate with URL Inspection and Rich Results Test where applicable.

The current app is a single-page Vite client-rendered application. It has one root document, a dynamically rendered tool catalog, modal-only tool workflows, no router, no existing robots.txt, and no existing sitemap. The sitemap should therefore expose the canonical homepage only until crawlable dedicated tool URLs are implemented. Avoid inventing URL routes that currently render no independent page content.

- Search Console ownership verification: https://support.google.com/webmasters/answer/9008080
  - Google lists HTML file upload, HTML meta tag, DNS/domain provider, Google Analytics, and Google Tag Manager methods. For this Vite project, HTML file upload or DNS verification is the cleanest choice; an HTML meta tag is also possible if the user supplies the token.

- Search Console Sitemaps report: https://support.google.com/webmasters/answer/7451001
  - After verification, submit `sitemap.xml` in the Sitemaps report. The report shows submission status and parsing/fetch errors. Google attempts to crawl soon after submission and may continue recrawling independently.
